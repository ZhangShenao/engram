# 1. 模型在算什么

第 0 章的「带参数的函数」，到这里变成一件具体的事。你平时调用的聊天模型，对外是一个函数：给它一组消息，它吐出一段文本。训练和推理内部都更窄。它每次只回答一个问题：

> 在已经看见的 token 后面，词表里每一个候选的概率是多少？

然后采样一个 token，把它接到上下文末尾，再问一次。整段回复是这个循环的产物。这叫自回归。

![自回归：一次只预测下一个 token](images/01-next-token.jpg)

图里的柱子是词表上的一小截概率。真实词表有 152064 项，大部分概率接近零。这些概率是 Softmax 从 logits 变来的，算法在第 0b 章。模型一次前向的直接产物是这一整张分布，采样器才决定吐出哪一个 token。权重就是第 0 章说的那组数字。Qwen2.5-14B 大约有 147 亿个，第 3 章再拆开。

写成条件概率就是：

```text
P(下一个 token | 已经看见的全部 token)
```

一整句的概率是这些条件概率连乘。句子是 `t1 t2 t3` 时：

```text
P(t1, t2, t3) = P(t1) × P(t2 | t1) × P(t3 | t1, t2)
```

训练把语料里真实出现的下一词的概率往上推，等价于把这句连乘的结果往上推。模型没有一个单独的「整段计划」。段是一次次抽样接出来的。

接的时候，已经吐出的 token 会变成下一步的输入。第一步如果抽到一个出戏的词，后面的分布是在这个词的条件上看的，错误会沿着回复往下传。这叫暴露偏差：训练时下一步看见的是语料里的真词，推理时看见的是自己上一步抽到的词。两条路径越长，差得越多。所以短回复上格式稳定，并不保证长回复后半段还在角色里。

## 温度和 top-p 在改哪一步

分布算完之后才采样。温度 `T` 先把 logits 除以 `T`，再做 Softmax。用第 0b 章的三个分数 `2.0`、`1.0`、`0.0`：

| T | 送进 Softmax 的分数 | 大约的概率 |
|---|---------------------|------------|
| 1 | 2, 1, 0 | 0.67, 0.24, 0.09 |
| 0.5 | 4, 2, 0 | 0.87, 0.12, 0.02 |
| 2 | 1, 0.5, 0 | 0.51, 0.31, 0.19 |

`T < 1` 把差距拉大，高分项更独占。`T > 1` 把差距缩小，长尾更容易被抽到。`T` 趋近 0 时，几乎总是取分数最高的那一个，这叫贪心解码。权重完全不动。

top-p 在概率已经算好之后，从高到低累加，保留累加刚好超过 `p` 的那些项，其余概率改成 0，再在剩下的项里重新归一化。它砍掉的是尾部，不改变权重。

Engram 的聊天补全把 `temperature` 设为 0.8，提取补全设为 0.2。微调改变的是除温度之前的 logits。采样只改变你从这张分布里怎么抽。

## 和 Agent 的分工

Engram 的 context-service 决定这一轮把什么放进上下文：角色卡、边界、记忆、摘要、最近对白。模型不拥有数据库，也看不见没放进来的历史。它只在给定上下文的条件下，给出下一个 token 的分布。记忆是否写回，发生在 `done` 之后的 Kafka 作业里，不改变这一次已经送出的上下文。

所以两件看起来像“模型没记住”的事，要分开：

- 上下文里根本没有那件事实。换模型也读不到。
- 上下文里有，分布却把概率给了别的说法。这才是模型行为。

检查器快照就是用来切开这两件事的。训练解决的是第二件，而且只在你的数据反复出现的那种第二件事上有效。

## 采样不是训练

上面的温度和 top-p 都发生在一次前向结束之后。把温度调低不会写回任何参数。若回复变呆，先看采样；若同一套采样下分布本身偏向客服腔，才是权重的问题。
